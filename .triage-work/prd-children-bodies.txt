## What to build
Implement async Web3Forms notification dispatch. After a successful checkout (order created in DB), the notification service dispatches a Web3Forms submission with order details. This happens asynchronously — it does not block or affect the order creation response. Each notification attempt is recorded in the `notification_attempts` table with status (`pending`, `sent`, `failed`), attempt count, last attempt timestamp, and error message on failure.

Admin can retry failed notifications from the order detail page via `POST /api/admin/orders/:id/retry-notification`. This re-dispatches the notification and updates the attempt record.

The notification payload includes: order reference, customer info, line items with prices, totals, and discount applied.
